# Radar de Talentos — dois dashboards, dois conjuntos de indicadores

## Objetivo
O módulo Audiência regional mostra a distribuição conhecida de visualizações, reproduções, ouvintes, seguidores ou alcance por talento e mídia (YouTube, Instagram, Spotify, TikTok). O módulo Tendências de eventos mostra quais modalidades e submodalidades as ticketeiras publicam em cada região. Um evento publicado não equivale a uma venda, nem uma visualização equivale a uma pessoa que comprará ingressos. Não somar métricas de mídias distintas. Nenhuma carga fictícia é distribuída.

## Abrir no VS Code
1. Pare servidor e worker anteriores e faça backup do banco existente (`npm run db:backup -- data/backups/pre-dashboard.sqlite`). Preserve o arquivo de dados e `config/operations.json` em local seguro.
2. Abra `Radar-Talentos-React-Node` no Node 22.12+ e execute `npm run db:init`, `npm test`, `npm run build` e `npm start`.
3. Acesse http://127.0.0.1:3000/ para eventos ou http://127.0.0.1:3000/audience.html para audiência. Ambos funcionam diretamente no Node, sem Vite.
4. Execute `npm run geo:sync -- 2025` para carregar a Base Geográfica Nacional, se necessário. Só sincronize quando tiver acesso autorizado às fontes. O raio usa distância geodésica entre coordenadas municipais disponíveis, não quilômetros rodoviários. Dados ausentes não recebem valor inventado.

## Audiência
Selecione mídia, indicador, fotografia (período, origem e qualidade), artista e filtros de modalidade/submodalidade. Escolha Brasil, região, estado, município ou pesquise uma cidade central e informe o raio. Os filtros são combinados por interseção. O mapa e gráficos são recalculados pela API. Clique nas bolhas ou nos estados para selecionar localidades; use o filtro vazio para voltar à visão ampla. A tabela lista artistas com dados no recorte, não uma classificação de todos os artistas existentes no país. O agregado municipal pode contar a mesma pessoa em mais de um artista, quando a métrica não é eventos de consumo. Estados sem valor positivo ficam cinza. Selecionar a mesma fonte e período é necessário para comparabilidade; cobertura parcial precisa ser interpretada como tal.

### Importação de dados autorizados
Cadastre o talento no banco por `npm run registry:import -- cadastro.json`, com ID, nome e modalidades verificadas (veja documentação da fase anterior). Os três conectores já existentes de audiência continuam aceitando relatórios com conta confirmada via `npm run audience:import -- report arquivo.json`. O novo importador genérico aceita contagens por município para qualquer uma das quatro mídias e grava a referência de autorização: `npm run regional:import -- relatorio.json`.

Contrato do arquivo (campos de texto devem ser preenchidos com metadados verdadeiros): `talent_id`, `network` (YouTube, Instagram, Spotify, TikTok), `metric` (conforme a rede), `period_start`, `period_end` (AAAA-MM-DD), `source`, `quality` (`verified` ou `estimated`), `report_ref`, `authorization_ref`, `coverage` (`partial` ou `complete`, padrão partial), `rows` (array de objetos `{municipality_code, value}`, código municipal e contagem inteira não negativa). Não importar percentuais como contagens. Relatórios apenas por país/estado não podem ser convertidos em municípios por suposição. A definição de verificado exige relatório oficial verificável; dados licenciados/modelados devem ser identificados como estimativas quando for o caso. O importador não substitui um relatório completo por parcial nem sobrescreve uma fotografia gerenciada pelo outro importador. Uma integração com provedor licenciado exige contrato, verificação de métricas e transformação do esquema real.

### Automação
`npm run ops:setup` cria configuração de exemplo se ainda não existir. Se a configuração já existir, adicione explicitamente `"enableRegionalAudience": true` no nível principal e copie as tarefas necessárias da configuração de exemplo. Tarefas de audiência não são ativadas por padrão: habilite apenas as fontes autorizadas, preencha escopo, autorização e identificador da conta (`accountId`) ou, no feed TikTok, do talento (`talentId`). Não compartilhe chaves no repositório. O worker usa os adaptadores `youtube`, `file` e `https` conforme as permissões. O feed TikTok segue o contrato do importador genérico; os outros feeds usam o contrato de conta confirmada da Fase 4. O conector YouTube Analytics requer canal confirmado e credenciais OAuth; não é possível obter a distribuição municipal de qualquer canal por meio de estatísticas públicas. Instagram, Spotify e TikTok só recebem dados geográficos quando existe um relatório/feed autorizado ou licenciado que realmente forneça tal granularidade. Não existe nesta entrega um conector nativo municipal para TikTok, Instagram ou Spotify.

Execute `npm run ops:check`, `npm run ops:doctor` e `npm run ops:once`. Para operação contínua, `npm run ops:worker`. Confira também a Central de sincronização no painel de eventos. A automação de eventos permanece separada dos indicadores de audiência; tarefas antigas de totais nacionais não são executadas. Mudanças de configuração exigem reiniciar o worker.

## Ticketeiras
O objetivo principal é medir as modalidades que cada plataforma publica em cada localidade, com ranking, gráficos, mapa, tabela modalidade × região, submodalidades, estados, cidades, período e raio. A data padrão é a primeira detecção; se a data de publicação original estiver disponível, pode-se usar o filtro correspondente. A primeira detecção não é a data oficial de anúncio. O sistema conta eventos únicos entre plataformas com deduplicação de identidade exata; listagens por fonte podem se sobrepor. Não interpretar volume de oferta como vendas ou procura. O ranking de atrações anunciadas fica como informação complementar, sem contaminar o ranking de audiência.

As integrações Ticketmaster, Sympla e Ingresse são mantidas, assim como as sete interfaces para feeds autorizados. As credenciais e feeds reais continuam obrigatórios. O acesso de produtor/organização não equivale à cobertura de mercado nacional. Confira o status de cada fonte e jamais interprete uma fonte sem dados como ausência de eventos.

## Validação e limites
52 testes automatizados aprovados no Node 22.16.0, incluindo importação, comparação por mídia, filtro por raio, modalidade × região, integração HTTP e sincronização de feed TikTok simulado. Build dos dois dashboards aprovado. A navegação Chromium em localhost foi bloqueada por política do ambiente; não foi possível certificar visualmente o fluxo completo. Nenhuma API externa foi ativada com credenciais reais, nenhuma base de produção foi modificada. A sincronização oficial de geografia continua dependente de acesso externo. Revise cobertura, classificação e identidade artística antes de tomar decisões comerciais. O suporte inicial usa municípios; não aceita polígonos desenhados livremente nem relatórios apenas estaduais sem municípios.
